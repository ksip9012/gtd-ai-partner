# 0003. サンプル Vault は作者と同じフォルダの形にし、作者の数値はスキルから参照ファイルに出し、v0.2 の機能は v0.1 から外す

- Status: Accepted
- Date: 2026-11-01

## Context

作者の Vault のスキルを汎用に直すにあたって、`notes/issue-1-inventory.md` で洗い出したもの（Vault のパス、作者の決めごと・数値、v0.2 に回す機能など）をどう扱うかを決める必要があった。

- パス: スキルは `gtd/004_todo.md` のような、番号付きのファイル名を名指しで読んでいる
- 作者の決めごと・数値: 運動の曜日、疲れの目安（Body Battery の値）、週の距離の上限、苦手な食べ物などが、スキルの本文に書かれている
- v0.2 に回す機能: Google カレンダーへの写し、朝のニュース、Garmin からの自動取得が、スキルの手順に入っている

## Decision

1. サンプル Vault（`sample-vault/`）は、作者の Vault と同じフォルダの形（番号付きのファイル名も同じ）にする。スキルのパスは変えない
2. 作者の決めごと・数値はスキルに書かず、サンプル Vault の参照ファイルに置く。スキルには「参照ファイルの数値をそのまま使う」「参照ファイルがなければユーザーに聞く」とだけ書く
    - AI パートナーの決めごと（トレーナーの物差し、助言の評価のチェックリスト）: `gtd/004_document/ai-partner/`
    - 生活の決めごと（定番のご飯、期限と誕生日）: `gtd/004_document/life/`（作者と同じ場所）
3. v0.2 に回す機能（Google カレンダーへの写し、朝のニュース、Garmin からの自動取得、外出先からの投げ込み）は、v0.1 のスキルから消す
4. スキルの本文からは、経緯の日付（「YYYY-MM-DD 決定」など）を外す。経緯は作者の Vault に残り、ここには「なぜそうするか」の理由だけを残す

## Consequences

- 作者の Vault から写すとき（`0002`）の直す量が少なくて済む
- 番号付きのファイル名は、初めて見る人には少しわかりにくい。README とサンプル Vault の `AGENTS.md` でフォルダの形を説明する
- 使う人は、参照ファイルの数値を自分のものに書き換えるだけで済む
- v0.2 で機能を戻すときは、スキルの手順に足し直す必要がある
