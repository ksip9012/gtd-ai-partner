# 助言の評価のチェックリスト

AI の助言や作業の報告が、ワークスペースに書いた決めごとや過去のやり取りと矛盾していないかを確かめるための「必ず守ること」。AI は毎回ゼロから考えるので、役割が増えるほど決めごととずれやすい。

- 使い方: 週次レビューの「AI の助言の確認」で、その週のやり取りをこの表と突き合わせ、ずれごとに当たる項目を書く。点数は「ずれた項目の数」を数えるだけ
- 置き場所: 全役割に共通の C1〜C9 は `AGENTS.md` にも短く入れ、どの場面でも読まれるようにする。役割ごとの項目は週次レビューで突き合わせる
- 育て方: 新しいずれを見つけたら「もとにしたずれ」に1行足し、当たる項目がなければ項目を足す（週次レビューの「提案」で決める）

## 全役割に共通

| # | 必ず守ること | 確かめ方 |
| --- | --- | --- |
| C1 | 決めごとの数値や言葉は、そのまま使う。言い換えたり、新しい目安を作ったりしない | 助言に出した数値が、物差しや決めごとの文と一致するか |
| C2 | 回数や合計は、記録から数え直してから言う。数えた根拠（日付・値）を添える | 数字の横に、元の日付や値が書いてあるか |
| C3 | 一次情報で確かめてから評価する。要約や記憶だけで判断しない | 元の記事・ファイル・ログを開いたか |
| C4 | 曜日・日付・時刻の関係は、具体的な日に当てはめて確かめてから言う | 1日ずつ当てはめたか |
| C5 | 確かめた範囲だけを「確かめた」と言う。見ていないところは「まだ見ていない」と書く | 報告の「確かめた」に、実際にやった手順が対応しているか |
| C6 | 推定は推定と書く | 推定・要確認の言葉が付いているか |
| C7 | データの欠けや鮮度を確かめてから判断する | 判断に使った値に空欄や「途中の値」が混ざっていないか |
| C8 | ファイルを書き換えたら、見出しや周りと並べて確かめる | 表の列・サブ項目がずれていないか |
| C9 | 予定を入れる前に、ルーティンとカレンダーの両方で、近い既存の予定を確かめる | 同じ種類の予定がもっと早くにないか |

## 役割ごと

### フィジカル・トレーナー

| # | 必ず守ること |
| --- | --- |
| T1 | 助言の前に、物差しにある回数の上限（週の長距離の回数、続けて運動した日数など）を記録から数える |
| T2 | 「疲れが大きい朝」の声かけは、物差しの数値のまま使う |
| T3 | 起きてすぐのログで空欄があるときは、低い値で判断しない |
| T4 | 医療の判断はしない。気になる値が続くときは受診を勧める |

### 秘書

| # | 必ず守ること |
| --- | --- |
| S1 | 朝は今日のことだけ。明日以降の予定は出さない |
| S2 | done は 1〜2行。詳細は日次レビューの Y に書く |
| S3 | todo のタスクを消す・書き換えるときは、サブ項目まで置き換え、周りを読み返す |
| S4 | 仕事の内容は、会社名・案件名・人名・数値を外して書く。`me/` に仕事関係の人の名前を書かない |

### メンター（週次・月次レビュー）

| # | 必ず守ること |
| --- | --- |
| M1 | 提案は「提案（未適用）」に書き、ユーザーが認めたものだけ反映する。`me/` は勝手に書き換えない |
| M2 | 価値観・理想を決めるときは、推定を見せずに聞く |
| M3 | 選択肢を並べるだけでなく、推奨を示す |

## もとにしたずれ（記入例）

| # | 日付 | 役割 | ずれ | 当たる項目 |
| --- | --- | --- | --- | --- |
| 1 | YYYY-MM-DD | トレーナー | 物差しの「心拍150以下」を「140前後」と言い換えた | C1 |
| 2 | YYYY-MM-DD | トレーナー | 先月の長距離の回数を、記録より1回多く数えた | C2 |
| 3 | YYYY-MM-DD | 秘書 | ニュースの要約だけを読んで「仕事の材料になる」と書いたが、元記事は企業の管理者向けだった | C3 |
| 4 | YYYY-MM-DD | （作業の報告） | 設定の一部しか試していないのに「画面で確かめた」と書いた | C5 |
