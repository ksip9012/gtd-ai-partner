# AGENTS.md

AIエージェント（Claude Code / Codex など）向けの共通ガイド。`CLAUDE.md` はこのファイルを読み込むだけにしてある。内容はここに一本化する。

## このリポジトリについて

個人のライフマネジメント用の Markdown のワークスペース。GTD (Getting Things Done) で管理していて、同時に **AI向けのパーソナルナレッジベース** も兼ねる。AIはここを読むことで、ユーザーの人物像・現状・判断基準を踏まえて手伝える。

## AIが最初に読むもの

1. `me/` — ユーザーの要約層。どんな質問でもまずここを読む
   - `000_profile.md`: 人物像・仕事・スキル・趣味
   - `001_values_goals.md`: 価値観・目標
   - `002_now.md`: 今の状況・進行中のプロジェクト（`updated` の日付を確認する）
   - `003_preferences.md`: 好み・判断基準・AIへの頼み方
2. 必要になったら原本（`gtd/` `reviews/` `logs/`）を読む

## 読み取りポリシー（2段階）

| レベル | 対象 | 扱い |
| --- | --- | --- |
| 通常 | 下の「要確認」以外のすべて | 自由に読んでよい |
| 要確認 | お金・キャリア・健康記録・身分証など、機微な情報を置いたフォルダ（例: `gtd/006_document/life/money/`） | 読む前にユーザーに確認する。外部サービスへは送らない。内容を `me/` などへ転記するときもユーザーに確認する |

- 要確認の領域は、自分のワークスペースに合わせて書き換える
- 仕事関係の人（同僚・取引先など）の名前は `me/` に書かない
- 仕事の内容を done やレビューに入れるときは、固有名詞（会社名・案件名・人名）や数値を外してまとめる

## 助言・報告で必ず守ること

全役割に共通の決まり。役割ごとの決まりは `gtd/006_document/ai-partner/advice-checklist.md`。

- C1: 決めごとの数値や言葉は、そのまま使う。言い換えたり、新しい目安を作ったりしない
- C2: 回数や合計は、記録から数え直してから言う。根拠（日付・値）を添える
- C3: 一次情報（元の記事・ファイル・ログ）で確かめてから評価する。要約や記憶だけで判断しない
- C4: 曜日・日付・時刻の関係は、具体的な日に当てはめて確かめてから言う
- C5: 確かめた範囲だけを「確かめた」と言う。見ていないところは「まだ見ていない」と書く
- C6: 推定は推定と書く
- C7: データの欠けや鮮度を確かめてから判断する（取りたてのログ、空欄のある行）
- C8: ファイルを書き換えたら、見出しや周りと並べて確かめる
- C9: 予定を入れる前に、ルーティンとカレンダーの両方で、近い既存の予定を確かめる

## `me/` の更新ルール

- `me/002_now.md` は週次レビューで、`me/001_values_goals.md` は月次・年次レビューで更新する
- AIが作業中にプロジェクトの開始・完了など大きな変化に気づいたら、`me/` の更新を提案する（勝手に書き換えない）
- 推定で書いた箇所は「推定」「要確認」と明示する
- 各ファイルの `updated:` を必ず更新する

## git

- ワークスペースの変更は、確認なしでコミットしてよい（スキルの「書いたらコミットしてよい」はこの決まりを指す）。push・削除・ほかのリポジトリは確認する
- 機微な情報を含むので、remote にはつながない（つなぐなら private にし、要確認の領域は別のリポジトリに分ける）

## ディレクトリ構成

```
.
├── AGENTS.md         # AI向け共通ガイド（このファイル）
├── me/               # AI向けのユーザー要約層
├── gtd/              # GTD管理
│   ├── 001_inbox.md          # 未処理のアイデア・タスクの収集場所
│   ├── 002_todo.md           # Next Action リスト（ルーティン・カレンダー・タスク）
│   ├── 003_project/          # 進行中プロジェクト（フォルダ名: YYYYMMDD_タイトル）
│   │   └── 00000000_archive  # 完了済みプロジェクト
│   ├── 004_waiting_for.md    # 誰かの返答待ち
│   ├── 005_someday_maybe.md  # いつかやるかもリスト
│   ├── 006_document/         # 参考資料
│   │   ├── ai-partner/       # AI パートナーの決めごと（トレーナーの物差し・助言の評価のチェックリスト）
│   │   └── life/             # 生活の決めごと（定番のご飯・期限と誕生日）
│   ├── 007_done_YYYY-MM.md   # 処理済みのタスク（月ごと）
│   └── 008_rules/            # GTDルール・チェックリスト
├── reviews/
│   ├── 00_trigger_list/  # 各レビューの手順
│   ├── 01_daily/         # 日次レビュー（年フォルダ/月単位ファイル）
│   └── 02_weekly/        # 週次レビュー（年単位ファイル）
├── logs/             # 睡眠・運動などのライフログ
└── zettelkasten/     # 知識ネットワーク
```

番号付きのファイル名は、ファイルの一覧で GTD の流れの順に並ぶようにするため。

## Markdownの記法

- 箇条書きのインデントはタブではなくスペース2個を使う

## GTD の運用ルール

- `gtd/002_todo.md` に追加するタスクは、物理的で具体的な行動にする（`gtd/008_rules/009_task_add_checklist.md` 参照）
- プロジェクトに属するなら、頭に `プロジェクト名:` を書き、詳細は `gtd/003_project/` のファイルに書いてリンクする。todo には Next Action のみ置く
- 完了したプロジェクトは `gtd/003_project/00000000_archive/` へ移動する
- 月ごとの完了タスクは `gtd/007_done_YYYY-MM.md` にまとめる

## レビューの形式

- 日次: 毎晩。`reviews/01_daily/YYYY/YYYY-MM.md` に月まとめで追記（`daily-review` スキル）
- 週次: 週に1回、朝。`reviews/02_weekly/YYYY.md` に追記（`weekly-review` スキル）
- 月次: 月末に近い週次レビューのあとに続けて（手順は `reviews/00_trigger_list/003_月次レビュー.md`）
