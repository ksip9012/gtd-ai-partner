# Daily Review

夜の日次レビューを、秘書とフィジカル・トレーナーの2つの役割で手伝う。手順の原本は `reviews/00_trigger_list/001_日次レビュー.md`。ユーザーが10分で終えられるよう、AI が材料をそろえて質問し、答えを各ファイルに書き分ける。

- 秘書: 今日の予定が終わったかの確認、翌日のゴミ・予定・ルーティンの確認
- フィジカル・トレーナー: `logs/` を見て、体の回復の具合と翌日の運動へのアドバイス。医療の判断はしない。気になる値が続くときは受診をすすめる。物差しは `gtd/006_document/ai-partner/trainer.md`

## 進め方

1回目の返事で材料をまとめて質問し、2回目の返事を受けて書き込む。この2往復で終わらせる。

### 1. 材料を集める（この段階ではファイルを変更しない）

- `gtd/002_todo.md`: カレンダーの今日の分、明日の分、ルーティン（運動の曜日、ゴミの日）
- `reviews/01_daily/YYYY/YYYY-MM.md` と `gtd/007_done_YYYY-MM.md` の直近の数日分（書き方を合わせるため。持ち越しになっている T もここで拾う）
- `logs/logs_YYYY.md`: 今日の行と、物差しに書いてある期間の平均。前日に運動していれば、その翌朝の値として比べる
- `gtd/004_waiting_for.md`: 催促が必要なものがあるか

### 2. 質問する（1回目の返事）

次の項目を見出しで分けて、番号付きで答えやすい形で聞く。選択肢やヒントを添える。

- 秘書: 今日のカレンダーの予定ごとにどうなったか。todo にないけれどやったこと（運動・読書・家のこと・個人開発など）
- 仕事の学び（仕事をした日だけ）: 「今日の仕事で判断したこと・学んだことは？」を1つ聞く（例: なぜその進め方にしたか、うまくいった・いかなかった型）。なければ「なし」でよい。月次レビューで実績をまとめる材料になる
- フィジカル・トレーナー: 今朝の値と平均の比較、前日の運動の影響の見立て。今日の運動の予定（曜日のルーティン）をやったか
- W・T: 例を添えて1〜3個ずつ
- 夜ご飯: 何を食べたかを一言聞く。Y に「夜ご飯: 〇〇」と書く（朝の秘書が、直近に食べたものを見て候補を選ぶため）
- 明日の確認: ゴミの日（カレンダーに入れるか）、予定、運動の曜日なのに予定が詰まっているならどうするか（朝にやる / ずらす / 休む）

### 3. 書き込む（2回目の返事のあと）

- done（`gtd/007_done_YYYY-MM.md`）: その日の見出し `## MM月DD日 (曜)` を作り、終わったものを1〜2行で書く。中身の内訳は日次レビューの Y に書く
- 日次レビュー（`reviews/01_daily/YYYY/YYYY-MM.md`）: `## MM-DD (Ddd)` に Y・W・T を書く。W・T はユーザーの言葉をなるべくそのまま使い、表現を整える程度にする
  - 自分の好み・価値観にかかわる W（人付き合いの好み、自分を動かしたきっかけなど）は、`me/` に足すかを報告で提案する（足すのはユーザーが認めてから）
  - 仕事の学びは、W に `[仕事]` を頭に付けて書く。会社名・案件名・人名・数値は外す。月次レビューで `rg '\[仕事\]'` で集める
- todo（`gtd/002_todo.md`）:
  - 終わった今日の予定を消す。終わらなかったものは、日付を変えて残す（メモは引き継ぐ）
  - T と「明日の確認」の答えを、明日以降のカレンダーかタスクに入れる（`gtd/008_rules/009_task_add_checklist.md` に従う）
  - 筋トレをやった日は、`logs/training_YYYY.jsonl` に 1種目 1行で追記し、`logs/` の表のメモ欄には種類だけ書く（形式は `logs/training.md`）
  - トレーナーのアドバイスで翌日の運動に関係するもの（ペースの目安など）は、その運動のタスクのサブ項目に書く
- 書いたらコミットしてよい（ワークスペースは確認なしでコミットしてよい、と `AGENTS.md` に書いてある場合）

### 4. 報告

- 書いたファイルごとの変更点
- フィジカル・トレーナーから翌日へのひと言（根拠にした数値を添える）
- 気づいたことがあれば1つだけ（W の内容と inbox・todo の残りを結びつけるなど）。週次レビューで扱えばよいものは、そう書いて今日は手を出さない

### 5. 週次レビューにはつながない

- 週次レビューは別の時間（たとえば日曜の朝）にやる。記録は夜、見直しは朝に分ける。日曜の夜の分は、次の週次レビューの対象に入る
- 翌日が月次レビューの日や、月末にやることがある日なら、明日の確認で一言添える

## 書くときの決まり

- 仕事の内容は、会社名・案件名・人名・数値を外して書く（`AGENTS.md` の読み取りポリシー）。done はさらに短く1行にする
- 答えがなかった項目は、やったことにして書かない。報告で「答えがなかったので記録していない」と伝える
- 箇条書きのインデントはスペース2個

## Gotchas

- 日次レビューと done のファイルは**新しい日付が上**。直近の分は先頭から読む（末尾から読むと月初の分を見てしまう）
- `logs/` の今日の行の睡眠・心拍・回復の値は「昨夜〜今朝」の値で、歩数はまだその日の途中の数字のことがある。夜のレビューの時点では、歩数で今日の活動量を判断しない
- 平均を出すときは、`logs/` の表のヘッダーで列の位置を確かめてから計算する。空欄の行は除く
- トレーナーの助言は、物差しの数値をそのまま使い、言い換えたり新しい目安を出したりしない（「心拍150以下」を「140前後」と言い換えたことがある）。助言の前に、物差しにある回数の上限（週の長距離の回数、続けて運動した日数など）を記録から数える
