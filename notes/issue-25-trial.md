# #25 今のスキルでサンプルを動かし直した結果（2026-11-15）

v0.1 のとき（[`issue-2-trial.md`](issue-2-trial.md)）と同じ形で、今のスキルを動かし直した。

- サンプルを一時フォルダに 4つ写し、それぞれ git に入れてから、画面なしの Claude Code（`claude -p`、Claude Code 2.1.311）で動かした
- プロンプトの頭で「今日は 2026-06-14（日）として扱う。ファイルは書き換えず、結果はチャットに出す」と伝えた
- 書き込み（Edit・Write）は禁止し、読むためのコマンド（`rg`・`git log`・`git status`・`ls`・`awk`・`head`・`cat`・`date`）だけを許した。朝の秘書だけ、天気のために `curl` も許した
- 終わったあと、4つとも `git status` で変更がないことを確かめた

## 天気だけ、スキルと呼び方を変えた

朝の秘書のスキルは、Open-Meteo の予報 API で動かした日の予報を取る。サンプルの「今日」は過去の日（2026-06-14）なので、このときだけ Historical Forecast API（`https://historical-forecast-api.open-meteo.com/v1/forecast`、`start_date` と `end_date` に 2026-06-14）を、スキルと同じ項目と座標で呼ぶように頼んだ。ふだん使うときは、スキルのとおり予報 API で今日の予報を取る。

## 気づいたこと

- **サンプルの誤りを見つけた**: 06/13 の日次レビューとハーフマラソンの memo に「はじめて 10km を超えた」と書いていたが、06/06 に 10.20km を走っていた。週次レビューが「回数は記録から数え直す」（C2）に当たるずれとして見つけた。この 2か所を「これまでで一番長い距離（10km 超えは 2回目）」に直した。v0.1 の README のデモの「昨日ははじめて 10km を超えるジョグ」も、この誤りをそのまま出していた
- 週次レビューは、06/12 の T にある「体が重ければ 8km でやめる」を、物差しにない数値として「要確認」に挙げた（数には入れなかった）。サンプルの人物が自分で決めた数値という設定なので、そのままにした
- 4つとも、システムの日付（2026-11-15）ではなく、頼んだ日付（06/14）で扱った
- `claude -p` を標準入力なしで動かすと「no stdin data received in 3s」の警告が出る。次からは `< /dev/null` を付ける
